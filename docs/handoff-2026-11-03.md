## For the SurrealDB blog post

- **Repo link:** this repository now has all the Agent Memory code (`packages/memory`, `apps/api/src/precedent-sync.ts`, `apps/planner-worker/src/precedents.ts`) and the gates.
- **What to say:**
  - Agent Memory is a recall index, never an authority. The Postgres `precedent_events` registry decides what's active, and the executor never holds a memory key.
  - There's one writer (the API, write key) and one reader (the planner, read key), each per organization.
  - Withdrawal supersedes the copy, so recall stops returning it.
  - Apply checks citations against Postgres.
- **What not to claim:**
  - "Memory shared across many agents": only the planner reads it.
  - Memory reacting to a plan approval being revoked: it doesn't.
  - Memory in the model-free apply step: there is none.
  - That a deployed demo uses memory: it doesn't, until item 4 is done.
- **Evidence:** both gates passed against the hosted service with a scripted model and testkit planning reads: the memory gate 7/7 and the app gate 5/5, three runs each, on 2026-11-02 and 2026-11-03 ([agent-memory.md](agent-memory.md)). These were not acceptance runs of a deployed app.
- **Service quirks:** the "Surprises" section of `docs/agent-memory.md` lists eight. The team decides whether to share them.

## Environment notes

- **Node and checks.**
  - Use Node 24.
  - Before a PR, run CI's set: `pnpm typecheck`, `pnpm lint`, `pnpm --filter @rehearsal/web build`, and `DB_TESTS=1 pnpm test`. Biome sorts imports (`npx biome check --write <file>`).
- **Postgres for tests.** Run a throwaway container on a free port if 5432 is taken (a WSL Postgres with other credentials took it on one Windows machine): `docker run -d --rm --name rehearsal-test-pg -e POSTGRES_USER=rehearsal -e POSTGRES_PASSWORD=pg -e POSTGRES_DB=rehearsal -p 55432:5432 postgres:17`, then `DATABASE_URL=postgres://rehearsal:pg@localhost:55432/rehearsal`.
- **Hosted memory gates.**
  - Commands: `MEMORY_GATE=1 pnpm test:memory` (about a minute) and `DB_TESTS=1 MEMORY_GATE=1 pnpm test:precedent-gate` (about 35 s).
  - They need `SURREAL_AGENT_MEMORY_URL`, `_CONTEXT` and `_ADMIN_KEY` in `.env`. The old `SURREAL_AGENT_MEMORY_KEY` name is refused; rename it.
  - Each run mints and revokes its own keys and erases its own scope.
- **Flaky test.** `packages/db/test/rehearsal-lifecycle.test.ts` ("a worker that dies after a send…") failed once in CI and passed on rerun, and passed 3/3 locally. It predates the sync. It needs a look.
- **Web e2e.** The Simulate UI's Playwright specs weren't rerun after the port, because the machine had no Playwright browser. They passed on the same web code before the port. Run `npx playwright install chromium` and `pnpm --filter @rehearsal/web e2e` once.
- **Lint on Windows.** A local, gitignored `.deploy/` folder can make `pnpm lint` fail. Lint a clean checkout or the changed files.
- **Python scripts on Windows.** Use `python -X utf8`. One committed README had a Windows-1252 dash byte; it was normalized during the port.
